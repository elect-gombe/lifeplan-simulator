`app/`（旧「FP計算」）を 0 から再設計・再実装したもの。計算エンジン・ドメインモデル・UI のすべてを新規に書いている。

## 設計方針

| 観点 | v2 の決定 |
| --- | --- |
| **入力の単位** | ユーザーが入力する金額は「万円」、DC 掛金だけ「円/月」。エンジン内部はすべて円。 |
| **時間軸** | 本人の年齢を唯一の軸にする。配偶者・子の年齢は差分から導出。 |
| **プラン** | 「別案を作る」はベースプランに**リンク**した別案を作る。入力パネルのセクション（家族/収入/生活費/住まい/子ども/運用/イベント/万一/前提）単位で「このプランで変更する」と上書きになり、それ以外はベースの変更に追従する。「独立させる」で値を固定した独立プランにできる（`domain/link.ts`）。比較ビューが設定の差分を自動抽出する。 |

## 印刷用レポート（FP 提案書スタイル）

レポートビュー下部の `PrintReport`（`features/report/PrintReport.tsx`）。A4 縦・ページ単位で改ページし、ブラウザの印刷から PDF にできる。構成: 総括 / 基本項目のご確認（家族・現在の収支・金融資産・住まい・保険と死亡退職金・リタイア後・イベント）/ 所得税・住民税の計算（メンバー別、計算式付き）/ ライフイベント表 / キャッシュフロー表（全年、10 年ずつ改ページ）/ 収支と資産のグラフ / お子さまのための支出（図: 子ごとの教育費・養育費の積み上げ＋同じ期間の年間収支、進路と教育費の合計）/ 住宅ローンの返済内訳と残高（図: 元金・利息・繰上返済の積み上げ＋残高の推移）/ 住宅ローンの返済推移と繰上返済の節約効果 / 車にかかる費用（図: 購入・ローンと維持費の積み上げ＋支払いの累計。車のイベントがあるときだけ）/ リタイア後の必要資金（退職時・+5・+10 年時点の累計）/ 公的年金の受取予想（基礎・厚生・在老停止）/ 万一時の備え（本人・配偶者。遺族の家計、必要保障額 vs 死亡保険金・死亡退職金）/ プラン比較。すべて既存の `YearRow` から導出し、レポート専用の計算は持たない。

### 紙に出たときの色（既定では背景が刷られない）

ブラウザの印刷は既定で背景色・背景画像を落とす（Chrome の「背景のグラフィック」は初期状態でオフ）。一方 SVG の `fill` や枠線は内容として扱われるので必ず出る。意味を持つ色は CSS の `background` に載せない。凡例の色見本（`charts/base.tsx` の `LegendItem`）を `<span style="background">` から `<svg><rect fill>` に変えたのはこのため。塗りの上に白文字を置く表現も、背景が落ちると白い紙に白文字になるのでレポートでは使わない。

ダークのトークン（`[data-theme="dark"]`）は `@media not print` で囲んである。印刷時は `:root` のライト値がそのまま効くので、ダークで表示したまま印刷しても紙はライトで出る。囲まないと、背景を刷らない設定では白い紙に薄い文字が乗り、刷る設定では暗い面に印刷用の濃い文字（`#555`）が乗って 2.3:1 まで落ちる。

点検は `emulateMedia({media:'print'})` では足りない（背景が落ちる挙動を再現しない）。`page.pdf({printBackground:false})` で実際に PDF を出し、`pdftoppm` で画像にして見る。

## 結果の書き方（断定を避ける）

このツールが出すのは、入力された前提のもとでのシミュレーション結果であって、将来の家計や制度の予測ではない。画面と印刷レポートの文言は次の方針でそろえている。

- 結果は「この試算では〜という結果です」「入力された前提のもとでは〜」と、前提つきで述べる。「〜します」と言い切らない。
- 助言は「〜が必要です」「〜してください」ではなく、「〜を変えると結果も変わります」「〜する余地があります」と選択肢の提示にとどめる。
- 保障の要否のように受け手の判断に直結するものは、「あくまでこの試算の前提のもとでは」と範囲を明示し、実際の判断には他の要素が絡むことを添える。
- 印刷レポートの総括には「入力された前提に基づく概算であり、将来の結果を保証するものではありません」を常に載せる。LLM 相談用テキストにも冒頭に同趣旨の一文を入れ、断定的な結論として読まれないようにする。

## パート収入の壁（社会保険・住民税）

- **社会保険の加入判定** `Member.socialInsurance`（`auto` / `join` / `dependent`、既定 `auto`）。auto は、給与 **106 万円**（`SI_ENROLL_ANNUAL`、月 8.8 万相当）以上の会社員は勤務先の社会保険に加入、それ未満で配偶者が被用者保険の被保険者かつ収入が **130 万円**（60 歳以上は 180 万円）未満なら被扶養者・第 3 号で保険料 0、どちらでもなければ国民健康保険＋国民年金。判定結果は `PersonTaxResult.breakdown.siStatus`（`employee` / `dependent` / `self` / `exemptLeave`）。
- **国保 均等割の軽減**（7 割・5 割・2 割）を判定所得から適用。
- **住民税の非課税限度額**: 合計所得が限度以下なら所得割・均等割とも 0。扶養なしは 45 万、扶養親族等 n 人なら 35 万×(n+1)＋31 万（均等割）／＋42 万（所得割）。`dependentsForRt` に同一生計配偶者＋子の数を渡す。
- これにより、配偶者が 100 万円のパートになると 所得税・住民税・社会保険料とも 0（手取り＝額面）になり、本人側で配偶者控除が満額 38 万円になる。

## 入力の追加（2026-09）

- 生活費の **内訳入力**（`living.detailed` / `living.items`）: 食費・電気・ガス・水道・通信・日用品・被服・医療・交通・教養娯楽・交際・こづかい・その他＋自由項目。内訳の合計が生活費スケジュールの現在値に同期する（将来の変化は従来どおり行で追加）。総務省 家計調査 2024 の平均（二人以上／単身、住居・教育・車・保険を除く概算 `LIVING_STATS`）を 1 クリックで投入できる。合計モードのままなら挙動は従来と同じ。

## 税・社会保険の計算根拠（年別内訳）

ダッシュボードで年をクリック → 内訳 → 「○○の税・社会保険の計算根拠」。収入→所得、社会保険料、所得控除（所得税/住民税）、課税所得と税額、節税効果、退職所得、手取りの各行に、その年の実数を入れた計算式を表示（`features/dashboard/TaxDetail.tsx`、エンジン側は `PersonTaxResult.breakdown`）。節税効果は「その控除がなかった場合」を同じ年の条件で再計算した差額。累進税率の階段図で課税所得の位置と限界税率・実効税率を示す。計算式の表示は切替可能（localStorage `lifeplan-tax-formula`）。

## 取り崩し（運用セクション）

- **売る順番** `invest.withdrawalOrder`: 特定口座→NISA（既定。非課税枠を長く残す）／NISA→特定口座／残高比例。現金が下限を割ったときの不足補填も、計画的な取り崩しも、この順で売る。特定口座は含み益 × 20.315% を売却時に課税（支出の「税（一時）」）。
- **計画的な取り崩し** `invest.withdrawal`: 必要なときだけ（既定）／定率（開始年齢から毎年、年初の NISA＋特定残高の x% を売却。残高が減れば額も減る）／定額（年 x 万円、インフレ連動。運用資産が尽きれば停止）。開始後は余剰現金を再投資しない設定が既定（`stopInvesting`）。売却額は税引前ベース、`flows.planned` に税引後の現金化額を記録し、開始年にマーカーを出す。
- **目標貯蓄** `invest.cashGoals`: 「○歳までに○万円を現金で用意する」を期間つきで登録。積立期間中は目標額を按分して現金のキープ上限に加算し、余剰が投資に回らず現金に残る（使う年の頭に満額、使った後は元に戻る）。`fromInvestments` をオンにすると、余剰で足りない年は差額を売却して現金に移し、売却を数年に分散する。運用セクションから、将来の住宅購入（頭金＋諸費用）を 1 クリックで目標に追加できる。積立開始年にマーカー、`flows.goalReserve` にその年のキープ額。
- 旧 JSON の `balancePolicy.withdrawalOrder`（旧エンジンでは未使用）は先頭が NISA なら「NISA→特定口座」に変換。

## レイアウトの方針（2026-09 調整）

- 本文は `max-w-[1500px]` で中央寄せ。超ワイド画面でチャートが極端に横長にならないようにする。

## ヘルプと見やすさ（2026-09 調整）

- **ヘルプは全ての数値入力・トグル・スライダーに**（`ui/primitives.tsx` の `HelpTip`）。ラベル横の ⓘ に説明を入れ、125 項目すべてが `help` を持つ。
- **吹き出しは `document.body` へポータル**。入力パネルは `overflow-y-auto` なので、通常の `absolute` だと端で切れる。実際の高さを測ってから上／下を決め、左右も画面内にクランプする。`Escape`・スクロール・リサイズ・外側タップで閉じる。
- **マウスはホバー、タッチはタップ、キーボードは `:focus-visible` で開く**。タッチでは `pointerenter` → `click` が連続するため、ホバー扱いで開くと即座に閉じてしまっていた（修正前はスマホで吹き出しが一切出ない）。
- **コントラスト**: 全ビュー・全入力セクション・モーダルをライト/ダーク両方で走査し、4.5:1（大きい文字は 3:1）未満をゼロにした。
  - `--ink-3` を `surface-3` の上でも 4.5:1 になるまで濃く。
  - **べた塗りの上の文字色**は `--on-fill-strong`（濃い塗り＝accent/good/warning/critical/s-cash → ライトは白）と `--on-fill-soft`（明るい系列色 → ライトは濃色）の 2 トークン。ダークはどちらも濃色（明るい塗りに白を載せると 1.8〜3.9:1 にしかならないため）。
  - 現金・預金の青 `--s-cash` を `--accent` と同じ `#2571cc` に。白文字で 4.42 → 4.87。
- **要素リセットを `@layer base` に移動**。レイヤー外に置いていたため `button { color: inherit }` が `@layer components` の `.btn-primary` / `.btn-ghost` を打ち消しており、**プライマリボタンの文字が白にならず 3.67:1（ダーク 3.31:1）だった**。ゴーストボタンも `--ink-2` にならず本文と同じ濃さだった。
- **タップ領域は 24px 角以上**（`.tap`）。ⓘ・トグル・セグメント・ピン解除・名前変更などの小さいアイコンは、見た目を変えずに擬似要素で当たり判定だけ広げる。
- **モーダル**は `aria-labelledby` で見出しと結び付け（フォーカストラップ・Escape・フォーカス復帰・背景スクロール抑止は既存）。
- **トグルの読み上げ名**はラベル部分だけ（`aria-labelledby`）。以前はヘルプ文がまるごと名前に入っていた。
- **連動中セクション**の減光は `.82`（`.65` では値が読めなかった）。リストの「編集」「削除」「進路」には対象名を含む `aria-label` を付ける。
- ダークのカードと背景の差は L* で 4.8（ライトは 3.5）、枠線とカードの差は 9.5（ライトは 8.8）。実測したうえで、ダークが見づらいわけではないと判断して変更していない。

## 表示の点検（2026-09、計測ベース）

チャート配色・印刷・キーボード・モバイル幅を通しで点検して直したもの。

- **系列色**: 住宅（時価）と住宅ローンが隣どうしなのに OKLab ΔE 13.2（ダーク 7.8）しか離れておらず、正常色覚でも見分けられなかった。住宅を桃 → 紫（`--s-home`）に移し、空いた桃を `--s-alt`（子どもの識別色）に回した。子どもの色順も「青→橙→緑→紫→黄→桃」に組み替え（紫と青が隣だと protan で ΔE 1.0）。ライト・ダークとも色覚シミュレーションを含む検証を通している。
- **印刷**: キャッシュフロー表が 1 ページ 15 年 = 最大 1,005px で、A4 縦・左右 10mm 余白の印刷幅 718px に対し右 3 割が切れていた。`YEARS_PER_PAGE = 10` とセル余白の縮小で全ページが 718px 以内に収まる（18 → 21 ページ）。
- **チャートが縮まない**: SVG に `width` 属性だけ付けていたため、コンテナが SVG の内在幅に引きずられて一方通行に広がり、ウィンドウを狭めても戻らずページが横スクロールしていた。全チャートの SVG に `max-w-full` を付与。
- **レポートの表**: 画面では表ごとに横スクロール（`.table-scroll`）。印刷では `overflow: visible` に戻す。
- **フォーカスリング**: 数値入力は内側の `<input>` が `outline-none` で、キーボードで辿ると現在位置が分からなかった。外枠に `.field-box:focus-within` のリングを追加。下線だけの入力にも `.underline-field:focus` を追加。
- **ダイアログのキーボード操作**: ウィザードとオンボーディングは `role="dialog"` を名乗りながら Escape で閉じられず、Tab がダイアログの外へ抜けていた。Modal と同じ挙動（Escape で閉じる／Tab は内部で循環／閉じたらフォーカスを戻す／背景スクロール抑止）にそろえた。Modal 側も、フォーカスが外にある状態からの Tab を引き戻すよう補強。ウィザードのステップ番号は白 25% の丸に白文字で 3.11:1 だったので、塗りと文字を反転（4.87／5.20）。
- **オンボーディングの実機確認**: 初回画面は `localStorage` を消さないと出せないため、`vite preview` を別ポートで立てて別オリジンとして検証した（利用中のデータには触れない）。4 ステップ × ライト/ダークで、コントラスト・タップ領域・読み上げ名・横スクロールの違反ゼロ。Escape でスキップ、Tab は内部で循環、390px でもはみ出しなし。
  - 途中で「消しても初回画面が出ない」ように見えたが、共有 URL のハッシュ（`#p=`）が残っていたのが理由で、仕様どおり。共有リンクを開いた人をオンボーディングに落とさない挙動。
- **入れ子のモーダル**: ウィザード／オンボーディングの中から子ども・住まいのモーダルを開くと、外側もキー操作を拾ってしまい Escape 1 回で両方閉じていた。`isTopmostDialog()`（DOM 順で最後の `[role="dialog"]` が最前面）で外側は手を引くようにし、Escape は内側だけを閉じる。
- **ヘルプの吹き出しと Escape**: ダイアログの中でヘルプを開いたまま Escape を押すと、吹き出しとダイアログが同時に閉じていた。`hasTransientOverlay()`（`[role="tooltip"]` が出ているか）を見て、1 回目は吹き出しだけ、2 回目でダイアログを閉じる。
- 配偶者の収入カードが住宅トークンを参照していて、系列色の変更に巻き込まれて紫に変わっていた。新設した `--s-alt`（元の桃）に付け替えて元の見た目に戻した。
- 検証: 5 ビュー × 9 入力セクション × モーダル 2 種をライト/ダークで走査し、文字コントラスト・タップ領域・横スクロールの違反ゼロ。90 タブ送りでリング欠けゼロ。ウィザード・子どもモーダル・共有ダイアログの 3 つで Tab / Shift+Tab とも外へ抜けないことを確認。コンソールのエラー・警告ゼロ。モバイル 390px は冷起動・縮小・復帰のいずれでも横スクロールなし。

## パフォーマンス方針（入力の反映が重くならないように）

- **計算は 2 段キャッシュ**（`state/useSim.ts`）: プランオブジェクトの同一性（WeakMap）と、計算に影響する内容のハッシュ（名前・色・リンク情報を除いた JSON、LRU 48 件）。名称変更・色変更・プラン切替・Undo/Redo では再計算しない。
- **リンク解決は同一性を保つ**（`domain/link.ts` の `resolveAll`）: 自分のデータとベースの解決結果が前回と同じなら同じオブジェクト（と同じ配列）を返す。無関係なプランの編集で他プランのグラフやシミュレーションが走らない。
- **結果ビューは `useDeferredValue` で 1 テンポ遅らせる**: 入力欄の更新を先にコミットし、チャート・年表・比較・レポートの再描画は後追い（連続入力中は途中状態を描かない）。
- **チャートは系列ごとに 1 つの `<path>`**（`charts/base.tsx` の `RectPath`）: 60 年 × 数系列の `<rect>` を個別に描かず、DOM 要素数を約 1/5 に。選択列だけを上に重ねて強調する。チャート・KPI・ナビは `memo`。
- 計測の目安（dev サーバー、2 プラン連動、ピン 4 つ）: シミュレーション自体は 1 プラン約 2ms。残りは React の描画コストで、`npm run build && npm run preview` の本番ビルドでは dev モードの検証オーバーヘッドがなくなりさらに軽い。
